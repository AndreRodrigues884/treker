     20260909010000_profiles.sql): enums fixos `modality`
     (gym/swimming/running) e `training_goal`, RLS (cada user só vê/edita

   - Landing page em "/" — tema escuro fixo com gradiente, copy em
     inglês, botões "Sign up" / "Log in". Se já houver sessão, redireciona
     automaticamente para /onboarding ou /dashboard.
   - /signup e /login — formulários com Server Actions (useActionState),
     Zod a validar. Sign up trata os dois casos: sessão imediata (dev
     local, confirmação de email desligada) ou "confirma o teu email"
     (produção, confirmação ligada).
   - /onboarding — escolha de desportos (gym/natação/corrida) e objetivos
     a partir de listas fixas (checkboxes, não texto livre), grava na
     tabela profiles e marca onboarding_completed.
   - /dashboard — layout com sidebar que só mostra as tabs das
     modalidades escolhidas; /dashboard/[modality] bloqueia o acesso a
     uma modalidade não escolhida; /dashboard/settings reutiliza o mesmo
     formulário do onboarding para mudar a escolha mais tarde.
   - Validado de ponta a ponta contra o Supabase local: criação de user
     real via API de signup, upsert do profile como esse user (a provar
     que a RLS deixa), e confirmado que só lê a própria linha — tudo via
     chamadas REST diretas, sem passar pela service_role key.
   - build, typecheck, lint e testes (vitest) confirmados a passar.
